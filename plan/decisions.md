# 技术选型（11-01 定）

每条：选了什么 · 为什么 · 什么情况下换。

## 1. 后端框架：继续用现有的 websockets 中枢，不换 FastAPI

- `hub/mock_hub.py` 已经有认证、自动发现、路由、日志、模式引擎，板子和模拟器都连着它。换 FastAPI 只会多一层、多一堆 bug，对演示零收益。
- 新逻辑放在新包 `brain/`（纯 Python，可单测），中枢只加一个 `ask` 处理函数调它。
- **换的条件：** 没有。比赛后想做 HTTP API 再说。

## 2. 大模型：一个 OpenAI 兼容客户端，三档可切换

| 档 | 用什么 | 什么时候用 |
|---|---|---|
| `ark` | **豆包（火山方舟 Ark）**，OpenAI 兼容接口 | 默认。中文好、快、和国内赛场网络兼容；评委认得 |
| `ollama` | 本机 Ollama + `qwen2.5:7b-instruct`（M1 Max 64 GB 跑得动，约 4.7 GB） | 场馆网络断了 / 方舟没开通 |
| `template` | 不调模型，按指标套模板生成一句话 | 最后的兜底，**永远能用** |

- 环境变量 `DESKBOT_LLM=ark|ollama|template`，密钥 `ARK_API_KEY`、`ARK_MODEL`（方舟控制台的模型 / 接入点 ID）写在 `data/.env`（已 gitignore）。
- 那个火山引擎 Agent Plan 链接：是方舟的套餐。**不是必须的**，按量付费开一个 API Key 就够；如果套餐已经买了就用它的 Key。别在这上面花超过 20 分钟。
- **不用 Claude 做线上推理**：国内场馆网络访问不稳，而且赛道评委更认国产模型。开发时用 Claude Code 写代码照常。
- 大模型只做两件事：① 路由规则认不出的问题，抽取意图和股票（function calling / JSON）；② 把算好的指标解释成一句话 + 三个要点。**不算数，不决定动作。**

## 3. 语音识别（ASR）：本机 mlx-whisper，规则纠错股票名

- `mlx-whisper` + `whisper-large-v3-turbo`：M1 Max 上 3 秒的话约 0.5–1 秒出字，离线，不用注册账号。
- 输出后用 `data/names.py` 的股票名表做模糊纠错（"宁德时带" → 宁德时代），再给路由。
- 火山引擎语音识别更准，但要单独开通语音应用（AppID + Token + WebSocket 协议），时间不够。**阶段 3 如果有空余**再接。
- **兜底：** 模拟器的输入框（打字）和浏览器麦克风（笔记本的麦克风，嘈杂现场比板子的 INMP441 可靠）。

## 4. 语音合成（TTS）：macOS `say -v Tingting`

- 已经用它做过 `voice_hello.h`，确定能出声、离线、零延迟账号。`say -o x.aiff` → `ffmpeg` 转 16 kHz 单声道 s16le → 发给板子播放。
- 板子喇叭只有 1 W，现场可能听不清：中枢可以**同时在笔记本上播放**（`DESKBOT_SPEAK=board|laptop|both`），展台默认 `both`。

## 5. 触发说话：按住屏幕说话为主，音量检测为辅

- 现场人多很吵，音量检测（现在的 4× 背景）会一直误触发。**按住屏幕 = 录音，松开 = 发送**，最可靠，评委一看就懂。
- 音量检测保留，安静时（评委单独站在面前）可以打开，用来演示"它会听"。

## 6. 动作语义：点头 / 摇头由规则决定

| 情况 | 动作 |
|---|---|
| 听到你开始说话 | 小点头一次（已实现） |
| 是非题答案是"是"（"宁德时代今天涨了吗？"→ 涨了） | 点头 2 次 |
| 是非题答案是"否" | 摇头 2 次 |
| 要投资建议 / 保证收益（"我该全仓买吗？"） | 摇头 + 护栏卡片 |
| 不认识的股票 / 没数据 | 摇头 1 次 + 说明 |
| 普通查询、对比 | 不动（或回答完点一下） |

在 `brain/gesture.py` 里，有单测。

## 7. 前端：留在 `sim/`（原生 JS），不上 React

- 模拟器已经是控制台 + 镜像 + 日志页，加一个问答面板就够。上框架要搭构建链，10 小时里不值。

## 8. 语言参数

- `lang=zh|en`，默认 `zh`。提示词双语，回答语言跟着参数走（对外国评委可以切英文）。股票名永远用中文。
