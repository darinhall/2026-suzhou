# 技术选型（11-01 定）

每条：选了什么 · 为什么 · 什么情况下换。

## 0. 网络拓扑（确认）

- 笔记本跑中枢 `hub/mock_hub.py`：一个 **WebSocket 服务器**，监听 `0.0.0.0:8765`（笔记本所有网卡）。它就是"本地服务器"。
- 板子是 **WebSocket 客户端**：开机连 Wi-Fi → 在 UDP 8766 广播 `{"t":"deskbot?"}` → 中枢回复 → 板子用**回复包的源 IP**拼出 `ws://<笔记本IP>:8765/robot` 连上来。**笔记本 IP 不写死**，换网络也能自动找到。
- 模拟器（浏览器，笔记本或手机）也是客户端，连同一个地址。中枢在中间转发：板子 ↔ 中枢 ↔ 模拟器。
- 前提：板子和笔记本在**同一个 Wi-Fi**（展台建议 iPhone 热点，都连它）。非本机连接要带令牌（`hub/.token`）。
- PandaAI 和大模型是**笔记本**去联网调用的；板子从不直接访问外网。

## 1. 后端框架：继续用现有的 websockets 中枢，不换 FastAPI

- `hub/mock_hub.py` 已经有认证、自动发现、路由、日志、模式引擎，板子和模拟器都连着它。换 FastAPI 只会多一层、多一堆 bug，对演示零收益。
- 新逻辑放在新包 `brain/`（纯 Python，可单测），中枢只加一个 `ask` 处理函数调它。
- **换的条件：** 没有。比赛后想做 HTTP API 再说。

## 2. 大模型：一个 OpenAI 兼容客户端，三档可切换

| 档 | 用什么 | 什么时候用 |
|---|---|---|
| `ark` | **豆包（火山方舟 Ark）**，OpenAI 兼容接口 | 默认。中文好、快、和国内赛场网络兼容；评委认得 |
| `ollama` | 本机 Ollama + `qwen2.5:7b-instruct`（M1 Max 64 GB 跑得动，约 4.7 GB） | 场馆网络断了 / 方舟没开通 |
| `template` | 不调模型，按指标套模板生成一句话 | 最后的兜底，**永远能用** |

- 环境变量 `DESKBOT_LLM=ark|ollama|template`，密钥 `ARK_API_KEY`、`ARK_MODEL`（方舟控制台的模型 / 接入点 ID）写在 `data/.env`（已 gitignore）。
- 那个火山引擎 Agent Plan 链接：是方舟的套餐。**不是必须的**，按量付费开一个 API Key 就够；如果套餐已经买了就用它的 Key。别在这上面花超过 20 分钟。
- **不用 Claude 做线上推理**：国内场馆网络访问不稳，而且赛道评委更认国产模型。开发时用 Claude Code 写代码照常。
- 大模型只做两件事：① 路由规则认不出的问题，抽取意图和股票（function calling / JSON）；② 把算好的指标解释成一句话 + 三个要点。**不算数，不决定动作。**

## 3. 语音识别（ASR）：本机 mlx-whisper，规则纠错股票名

- `mlx-whisper` + `whisper-large-v3-turbo`：M1 Max 上 3 秒的话约 0.5–1 秒出字，离线，不用注册账号。
- 输出后用 `data/names.py` 的股票名表做模糊纠错（"宁德时带" → 宁德时代），再给路由。
- 火山引擎语音识别更准，但要单独开通语音应用（AppID + Token + WebSocket 协议），时间不够。**阶段 3 如果有空余**再接。
- **兜底：** 模拟器的输入框（打字）和浏览器麦克风（笔记本的麦克风，嘈杂现场比板子的 INMP441 可靠）。

## 4. 语音合成（TTS）：喇叭是**辅助**，屏幕文字是主角

- **不依赖喇叭。** 回答的那句话（`say`）**一定以字幕形式显示在答案卡底部**；喇叭同时念出来，听不清也不影响理解。
- 默认引擎：macOS `say -v Tingting`（已经用它做过 `voice_hello.h`，离线、零账号）→ `ffmpeg` 转 16 kHz s16le → 板子。
- **豆包语音合成（火山引擎 TTS）是可选升级**，`DESKBOT_TTS=say|doubao`：声音自然很多，评委能感觉到"有性格"，但要单独开通语音应用（AppID + Token），且每句话要联网。**只在阶段 1 完成、方舟已经能用之后再做**（T08c），失败自动退回 `say`。
- 剧本里的固定句子（"我不做买卖建议""没听清"）提前合成好缓存，不受网络影响。
- `DESKBOT_SPEAK=board|laptop|both|off`，默认 `board`。

## 5. 触发说话：按住屏幕说话为主，音量检测为辅

- 现场人多很吵，音量检测（现在的 4× 背景）会一直误触发。**按住屏幕 = 录音，松开 = 发送**，最可靠，评委一看就懂。
- 音量检测保留，安静时（评委单独站在面前）可以打开，用来演示"它会听"。

## 6. 动作语义：点头 / 摇头由规则决定

| 情况 | 动作 |
|---|---|
| 听到你开始说话 | 小点头一次（已实现） |
| 是非题答案是"是"（"宁德时代今天涨了吗？"→ 涨了） | 点头 2 次 |
| 是非题答案是"否" | 摇头 2 次 |
| 要投资建议 / 保证收益（"我该全仓买吗？"） | 摇头 + 护栏卡片 |
| 不认识的股票 / 没数据 | 摇头 1 次 + 说明 |
| 普通查询、对比 | 不动（或回答完点一下） |
| **主动提醒（异动）** | **转头看你**（`look`），3 级再加点头 / 摇头（涨 / 跌）。见 §12 |

在 `brain/gesture.py` 里，有单测。

## 7. 前端：留在 `sim/`（原生 JS），不上 React

- 模拟器已经是控制台 + 镜像 + 日志页，加一个问答面板就够。上框架要搭构建链，10 小时里不值。

## 8. 语言参数

- `lang=zh|en`，默认 `zh`。提示词双语，回答语言跟着参数走（对外国评委可以切英文）。股票名永远用中文。

## 9. 吉祥物：熊猫（替换现在的"一对眼睛"）

- 机器人外壳本来就是黑白的，屏幕上的脸改成**熊猫**：白脸、黑耳朵、**黑眼圈（眼斑）里的眼睛**、小黑鼻子。名字和 PandaAI 也呼应。
- 所有表情（待机、在听、思考、开心、睡觉、玩球）保留，只换画法：眼睛仍是现在的胶囊形，外面加倾斜的黑色眼斑；"在听"时耳朵动一下。
- **配色改成"熊猫"主题**（`design/tokens.json` 加一套 `panda`，模拟器和板子一起换）：墨黑 + 暖白（不用纯白，这块屏偏冷会发蓝，过 `devColor()`）。
  - 涨红跌绿照旧（A 股习惯）。**不用竹子绿当强调色**，会和"跌"混淆；强调色用黑。
- 答案卡、盯盘卡也换成黑白主题，和外壳统一。米黄主题保留成可选项，不删。
- 任务：T14。

## 10. 休市：问答也用"周五回放时钟"

- 中枢已经有**回放**：10-30（周五）真实 5 分钟线按 `replay.speed` 加速播放，屏幕写 `10-30 13:35`，不冒充实时（《场景.md》"为什么要回放"）。
- 问答接到同一个时钟上：回放到 10:35 时问"宁德时代涨了吗"，就按 10:35 那一刻的价格回答（点头 / 摇头可能和收盘时不一样，演示更有"盯盘"的感觉）。卡片来源写「PandaAI · 10-30 回放 10:35」。
- 回放关掉时按收盘回答（「10-30 收盘」）。周一开盘后 `live` 照旧尽力而为。
- PandaAI 能不能更细（1 分钟线）：SDK 有 `get_stock_min(frequency="1m")`，T03 里试一下，能拿到就用 1 分钟线回放，更顺滑。

## 11. 测试分两层：离线 + 真数据

- **离线层**（默认，`pytest`）：假行情 + 假大模型，几十毫秒跑完，任何时候都能跑。
- **真数据层**（`DESKBOT_LIVE=1 pytest -m live`）：真的登录 PandaAI、取 10-30 的数据、调真的大模型（方舟 / Ollama），检查数据对得上、回答 JSON 合格、数字没被编造。用来确认我们和 PandaAI 接口一直是同步的。**每完成一个后端任务、以及上台前，各跑一次。**

## 12. 实体机器人的卖点：提醒阶梯（为什么不是一个 App）

- **余光比屏幕灵敏。** 人对视野边缘的"动"比对数字和颜色敏感得多。专心工作时，股票小组件等于不存在；一个转过头来看你的熊猫，不用你看它就能注意到。
- **不发通知，按重要程度"动"。** 0 级只改数字、1 级瞥你一眼、2 级转头看你、3 级叫你。手机通知只有"响 / 不响"；机器人有一整条从轻到重的阶梯，打扰程度和事情的重要程度相匹配。
- （以后）阶梯可以由交易人格决定（T16，已搁置）。
- **身体比弹窗更能拦住冲动。** 弹窗点一下就关了；桌上的熊猫对你摇头，是一个小小的、带社交感的"减速带"。
- 好看是钩子，不是理由：先让人注意到它，再用提醒阶梯说服人留下它。
- 推销用语：「它不发通知，它转头看你。」「不用盯盘，它替你盯；该提醒时转头看你，该拦你时对你摇头。」
